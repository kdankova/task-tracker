# Допущения

Что ТЗ не оговаривает явно и как это решено.

## Пользователи

- **Email без учёта регистра.** Хранится в нижнем регистре; `USER@example.com` после
  `user@example.com` → `409`. Строго говоря, локальная часть email по RFC
  регистрозависима, но на практике почтовые сервисы так её не трактуют, а дубли
  аккаунтов — реальная проблема.
- **Пробелы по краям `name` обрезаются**; имя только из пробелов считается пустым → `422`.
- **Ограничения длины:** `name` до 255 символов, email — по правилам `email-validator`.

## Задачи

- **Переходы между статусами не ограничены.** ТЗ не задаёт машину состояний, поэтому
  разрешён любой переход, включая возврат из `done` / `cancelled`. Некорректным
  считается только значение вне списка статусов → `422`.
- **Повторная установка текущего статуса** — идемпотентный no-op: `200`, `updated_at`
  не меняется.
- **Статус при создании задать нельзя** — всегда `new`. Лишние поля в теле запроса
  отклоняются с `422` (`extra="forbid"`), а не игнорируются молча.
- **Пустое или пробельное `description` сохраняется как `null`.**
- **Ограничения длины:** `title` до 255 символов, `description` до 10 000.
- **Удаление физическое**, ответ — `200 {"ok": true}`, как в ТЗ (а не `204`).

## Список и статистика

- **Ответ списка — конверт** `{items, total, limit, offset}`, а не голый массив: без
  `total` клиент не построит пагинацию.
- **Пагинация:** `limit` от 1 до 100, по умолчанию 20; `offset` ≥ 0. Offset за
  пределами данных возвращает пустой `items` с корректным `total`.
- **Сортировка:** новые сверху (`created_at DESC, id DESC`).
- **Несуществующий пользователь** в списке и статистике → `404`, а не пустой результат:
  иначе опечатку в id не отличить от пользователя без задач.

## Общее

- **Время в UTC с таймзоной** (`2026-06-05T12:00:00Z`). В примере из ТЗ время без
  таймзоны; такое значение неоднозначно, поэтому таймзона указывается явно.
- **Аутентификации и авторизации нет** — ТЗ их не требует. Любой клиент может работать
  с задачами любого пользователя.
- **id — `BIGINT`.** Path-параметры и `offset` вне диапазона → `422`.
- **Миграции применяются при старте API-контейнера.** Для нескольких реплик их нужно
  вынести в отдельный шаг деплоя.
